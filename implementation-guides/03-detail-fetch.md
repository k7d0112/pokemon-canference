# 実装課題3: ポケモン詳細取得

## Claude Codeへの実装プロンプト

```
ポケモンリストから選択したポケモンの詳細情報をAPIから取得する機能を実装してください。
実装課題1と2が完了している状態に、詳細データの取得処理を追加します。

## 前提条件
- 実装課題1が完了していること（ポケモン一覧が表示されている）
- 実装課題2が完了していること（詳細表示UIが実装されている）
- ポケモンをクリックした際に詳細データを取得する仕組みを作る

## 実装場所
- ファイル: src/app/page.tsx
- 関数名: handlePokemonSelect（既存の関数を拡張）

## 機能要件
1. リストのポケモンをクリックすると詳細データを取得
2. 日本語名を含む完全な詳細情報を取得
3. ローディング中は適切な表示（スピナーなど）
4. エラーが発生してもアプリは継続動作
5. モーダルでの詳細表示が完全に機能する

## 完了後の動作
- ✅ ポケモンをクリックするとメイン画面に大きく表示される

- ✅ 日本語名とタイプがカラフルに表示される
- ✅ ステータスがプログレスバーで視覚化される
- ✅ ローディング中は適切なスピナー表示

## 実装仕様

この実装では、既存の簡易版の選択処理を拡張して、
実際にAPIからポケモンの詳細データを取得できるようにします。

### 実装の背景と目的

現在のhandlePokemonSelect関数は、実装課題1でも動作するように
簡易版として実装されています。この課題では、この関数を拡張して
実際にAPIから詳細データを取得し、美しい詳細表示を実現します。

### 関数の設計要件

#### メモ化とパフォーマンス
- useCallbackでメモ化してレンダリングを最適化
- 依存配列は空配列 [] を維持（関数の再作成を防ぐ）
- パラメータ: pokemonUrl（string型）

#### エラーハンドリングパターン
非同期処理では必ずtry-catch-finally構文を使用して、
成功・失敗・後処理を適切に管理します。

### 実装手順

#### Step 1: ローディング状態の管理
ポケモンをクリックした瞬間にローディング状態を開始し、
ユーザーに処理中であることを明確に示します。

**実装要件:**
- setLoadingDetail(true)でローディング開始
- メイン表示エリアにローディングスピナーが表示される
- ユーザーは処理中であることが分かる

#### Step 2: 選択状態の保存
どのポケモンが選択されているかをUIで明示するため、
選択されたポケモンのURLを状態として保存します。

**実装要件:**
- setSelectedPokemonUrl(pokemonUrl)で選択状態を保存
- リスト内で選択中のポケモンがハイライト表示される
- ユーザーが現在どのポケモンを見ているかが明確になる

#### Step 3: URLからポケモンIDを抽出
PokeAPIでは各ポケモンに数値IDが割り当てられています。
URLからこのIDを抽出する必要があります。

**処理要件:**
- pokemonService.extractIdFromResourceUrlを使用
- URLの例: "https://pokeapi.co/api/v2/pokemon/25/" → ID: 25
- この数値IDを使って詳細APIを呼び出す

**エラーハンドリング:**
- IDが取得できない場合はエラーをスロー
- 条件: if (!pokemonId) throw new Error('Invalid Pokemon URL')
- 不正なURLからアプリケーションを保護

#### Step 4: 詳細データの取得
ポケモンサービスを使用して、基本データと日本語名を
一度に取得します。

**API呼び出し要件:**
- pokemonService.getPokemonDetailWithJapaneseNameを使用
- このメソッドは内部で以下を自動実行:
  - 基本的な詳細データ（タイプ、ステータス、画像など）
  - 日本語名データ
  - 両方のデータを結合した完全なオブジェクト

**データの構造:**
取得されるデータには以下が含まれます:
- 基本情報: name, height, weight, sprites（画像）
- タイプ情報: types配列（ほのお、みず、くさなど）
- ステータス情報: stats配列（HP、攻撃、防御など）
- 日本語名: japaneseName

#### Step 5: データの保存とUI更新
取得した詳細データを状態に保存し、UIが自動的に
更新されるようにします。

**実装要件:**
- setSelectedPokemon(pokemonDetail)でデータを保存
- Reactの状態管理により、以下が自動更新される:
  - メイン表示エリアのポケモン画像と名前
  - 詳細モーダルの内容
  - 「i」ボタンが有効になる

### エラー処理とユーザー体験

#### エラーケースの対応
以下のような問題が発生してもアプリケーションは継続動作:
- 不正なURL形式
- ネットワーク接続の問題
- APIサーバーのダウン
- データの形式エラー

**エラー処理の実装:**
- console.error('ポケモン詳細の取得に失敗しました:', error)
- エラーログをコンソールに出力（開発者向け）
- ユーザーには影響せず、アプリケーションは正常継続

#### 確実なローディング終了
成功・失敗に関わらず、必ずローディング状態を解除し、
UIが固まることを防ぎます。

**後処理の実装:**
- finallyブロックでsetLoadingDetail(false)
- try-catchのどちらのパスを通ってもローディング終了
- ユーザーは次の操作を継続できる

### 実装時の重要なポイント

#### 1. 非同期処理のパターン
```
async (pokemonUrl: string) => {
  try {
    // 成功時の処理フロー
  } catch (error) {
    // エラー時の処理フロー
  } finally {
    // 必ず実行される後処理
  }
}
```

#### 2. 状態更新の順序
1. ローディング開始 → ユーザーに処理開始を通知
2. 選択状態保存 → UIでハイライト表示
3. データ取得 → APIからの情報取得
4. データ保存 → UIに反映
5. ローディング終了 → ユーザーに処理完了を通知

#### 3. useCallbackの使用理由
- コンポーネントの再レンダリング時に関数が再作成されるのを防ぐ
- パフォーマンスの最適化
- 依存配列を空にすることで、関数の内容を固定

### 期待される動作の流れ

#### 通常の成功パターン
1. ユーザーがリスト内のポケモンをクリック
2. 即座にローディングスピナーが表示される
3. リスト内で選択したポケモンがハイライトされる
4. APIからデータを取得（通常1-2秒）
5. メイン画面にポケモンの画像と名前が大きく表示される
6. 「i」ボタンが活性化され、クリック可能になる
7. 「i」ボタンをクリックすると詳細モーダルが開く
8. タイプが色付きバッジで表示される
9. ステータスがプログレスバーで表示される

#### エラー発生時のパターン
1. ユーザーがポケモンをクリック
2. ローディングスピナーが表示される
3. APIエラーが発生
4. コンソールにエラーログが出力される
5. ローディングが終了し、ユーザーは他の操作を継続できる
6. アプリケーションは正常に動作し続ける

## 使用するサービスと関数

### pokemonService
- **extractIdFromResourceUrl**: URLから数値IDを抽出
- **getPokemonDetailWithJapaneseName**: 詳細データと日本語名を一括取得

### 状態管理関数
- **setLoadingDetail**: 詳細取得のローディング状態管理
- **setSelectedPokemonUrl**: 選択されたポケモンのURL管理
- **setSelectedPokemon**: 詳細データの管理
```
